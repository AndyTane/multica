# CLAWSTA-118 R1：免邮件加入实测

使用仓库 `scripts/native-windows.ps1` 的 `Prepare -Clean`、`Build`、`Start` / `Stop`，指定上述独立数据库和端口。只复用缓存中的 PostgreSQL 二进制，未复制现有部署的数据、配置或凭据。初始操作员按安装脚本的方式在新库建账号，再用主机工具 `local-auth create` / `grant-admin` 准备测试管理员。两位同事均通过浏览器中的 "添加用户并创建邀请" 创建并自行设密；没有直接写入他们的成员关系、完成状态或权限。

DEV 发信分支会在标准输出打印链接。因此仅在**隔离目录的 supervisor 副本**中，为 API 标准输出接入内存过滤：原始行丢弃，日志只记录 `DEV invitation fallback observed; delivery provider absent; details discarded.`。API / 网页二进制保持原样；没有真实投递。截图在捕获时遮挡输入框及分享链接；未启用带请求正文的 trace / HAR。

## 浏览器与后端结果

最终一轮共 36 项检查通过。操作员、同事、未登录访客及第二位同事使用独立 Chromium 上下文；加入、复制、设密及撤销均实际点击页面。

| 场景 | 浏览器结果 | 后端核对 |
| --- | --- | --- |
| 无发信配置，先邀请尚无账号的邮箱 | 显示 "已发送邀请"，"待接受邀请" 出现记录 | POST 成员邀请 201；`workspace_invitation.status=pending`，`invitee_user_id` 为空；观察到脱敏 DEV 分支状态 |
| 创建工作区分享链接 | "成员 → 分享链接 → 创建分享链接 → 生成 → 复制链接" 可用 | 返回 201，角色 `member`，有效期 168 小时 |
| 仅持分享链接，没有账号 | 显示 **Log In to Join**，点击进入登录页；注册页只有邀请入口 | 无邀请的开放注册请求返回 403，开放注册设置始终为 false |
| 实例管理员添加同事 | 从 "用户与注册" 复制账号邀请，在新上下文设登录名及密码，返回 200 | 激活后成员关系数为 0，`is_instance_admin=false`；账号并未自动加入工作区 |
| 重用已消费的账号邀请 | 再次提交显示 "邀请无效或已过期。" | 返回 400，没有再次设密成功 |
| 同事加入目标工作区 | 在首次上手引导页重新打开分享链接，点 **Join Workspace**；经过下述刷新恢复后，可见目标任务，刷新仍可见 | 加入返回 200；恰好 1 条该同事的成员关系，角色 `member`，`onboarded_at` 非空 |
| 检查原邮箱 pending | 管理员刷新 "待接受邀请"，原记录已不显示 | 原邀请自动改为 `accepted`；管理员创建的账号为 `email_verified=true` |
| 撤销未使用的邮箱邀请 | 另建一条未使用的邮箱邀请，点击行尾叉号，再点 "确认"，记录消失 | DELETE 返回 204；对应邀请行被删除，**不是**保留 `revoked` 状态；已加入同事仍能看任务 |
| 撤销分享链接 | 在 "分享链接" 点击 "撤销链接"；第二个已激活账号打开旧链接显示失效 | 第二个账号尝试加入返回 404，成员关系数为 0；原成员刷新后仍可看任务 |

最终目标工作区的独立数据库复核：成员数 **2**（操作员 owner + 同事 member）、任务数 **1**、原邮箱邀请 `accepted` **1**、pending **0**；分享链接 `is_active=false`、`use_count=1`、`role=member`。第二位同事只启用了账号，没有加入任何工作区。

注意：任务书提出的 "未验证账号可能留下 pending" 与这条管理员添加账号的路径不同。基线 `CreateUser` 使用数据库默认 `email_verified=true`；开放注册的 `CreateUnverifiedUser` 才显式设 false。本次未打开开放注册，也未用数据库改标记来制造未验证账号。该分支仅保留源码说明，不当作本次浏览器实测。

## 两个需要交回负责人的产品事项

1. **默认便携 admin 不等于实例管理员。** `deploy/portable/install.ps1` 的 `Install-PortableAccount` 建账号、密码、工作区和守护进程凭据，未调用 `grant-admin`；`576_instance_admin.up.sql` 默认 false，本次也从数据库结构核对。工作区 owner 可以管理分享链接，但没有 "用户与注册" 入口。本次初始操作员的实例权限是**隔离测试准备**，不能据此说全新便携包已默认具备这条完整流程。实际部署缺实例管理员时，需要负责人确定初始化方案；R1 没有改公司账号权限。
2. **加入成功后偶发回到引导。** 本轮观察到 `/api/share-links/join` 返回 200 后进入目标任务页，随后又回到 `/onboarding`，页面出现 "我已经用过了"；刷新该页后自动进入目标看板，任务可见，后续刷新稳定。源码定位：`apps/web/app/join/page.tsx` 在加入成功后刷新工作区列表，但没有刷新当前账号；`apps/web/app/[workspaceSlug]/layout.tsx` 使用客户端缓存的 `onboarded_at` 执行引导跳转。后端已经在加入事务中标记完成，页面身份状态尚未同步。本批只记录现象、依据和刷新办法，不修改产品认证或路由。
