- 独立便携测试目录、全新 PostgreSQL 集群和数据库；数据库 / API / 网页 / HTTPS 分别为回环端口 17439 / 18439 / 13439 / 14439。
- 安装脚本为本次候选代码。API 和 `local-auth.exe` 使用现存 v0.2.1 包的未改动二进制；网页由候选源码完成 Next.js 生产构建，并按现有打包工具整理依赖后装入测试副本。不是公司部署或新的发布包。
- Windows PowerShell 5.1 实际执行安装、恢复、升级及教程命令。Playwright Chromium 使用独立浏览器上下文；HTTPS 测试忽略隔离环境自签证书，不安装根证书，不开放 LAN。
- 首次搭建因测试复制命令漏了一个前端依赖目录而中止，修正副本后在尚无账号的空库继续，实际走新操作员创建与授权分支。生产构建途中 C 盘缓存空间不足，删除本 checkout 的生成缓存后构建成功。升级演练限定子进程优先使用 Windows 自带 tar，避开本机 Git tar 对盘符的解析冲突。这些准备处理没有进入产品改动。
- 跳过守护进程、启动项和浏览器证书安装；为普通 Setup 重跑及升级屏蔽了测试副本中无关的 daemon 启停边界，未运行真实智能体。权限、账号、工作区、备份、迁移、网页及浏览器请求均实际执行。
- 只使用本轮合成账号和任务；没有访问公司服务或读取公司成员数据，没有发送邮件。截图屏蔽所有输入框及能力链接，不记录 trace / HAR、密码、cookie 或 token。

## 安装与现有部署的主机命令

| 场景 | 实际结果 |
| --- | --- |
| 空库首次创建操作员 | `Get-PortableIdentity` 在同一事务返回真实 UUID 和 `created=true`，现有 `grant-admin` 只授予这个新账号。数据库确认 `is_instance_admin=true`。 |
| 已安装目录重跑 Setup | 先由测试夹具将操作员的实例权限撤销。实际重跑 Setup 只启动原部署；数据库仍为 false。 |
| 中断后恢复 Setup | 暂存安装报告以进入恢复分支，账号已经存在；运行完整账号步骤后仍为 false，没有恢复已撤销权限。 |
| 升级路径 | `upgrade.ps1 -Force` 同版演练完成真实备份、停止、Stage、迁移及重启；前后均为 1 账号 / 1 工作区 / 0 任务，已撤销的实例权限保持 false。 |
| v0.2.1 显式主机初始化 | 直接提取教程的两个 PowerShell 代码块，仅替换测试安装目录。使用与 v0.2.1 包内 SHA-256 相同的 `local-auth.exe`。登录账号的 UUID / 邮箱与安装记录一致后才执行 grant，数据库变为 true。 |
| 身份不匹配 | 将待核对 UUID 改为测试用错误值，教程在授权前报“当前登录身份与安装记录不一致”，原账号仍为 false。 |
| 重复显式初始化 | 第二次成功并提示 `already granted`；没有新建账号。故意设置错误的进程级 `DATABASE_URL` 后执行也只连接本部署，结束后原进程设置被还原。 |
| 网页入口 | 重新登录，默认操作员可见“用户与注册”及添加用户控件；同事没有实例权限，开放注册保持关闭。 |

安装单元测试还覆盖：已有账号不调用授权、授权 UUID 与凭据 UUID 一致、外部数据库环境不会重定向 grant、授权非零退出及工具缺失会中止、缺失 / 多条 / 无效创建结果会拒绝继续。没有修改接管或升级脚本的授权行为。

## 浏览器结果：23 项检查通过

逐项脱敏结果见 [browser-checks.json](browser-checks.json)。

两个新同事都通过“用户与注册”页面取得邀请、在浏览器自行设密；加入前数据库中均为 0 工作区关系、非实例管理员。没有手写这两人的密码凭据、成员关系或 onboarding 标记，也没有创建个人工作区。

1. **正常加入**：同一浏览器从上手引导打开普通成员分享链接，点击 Join Workspace。导航前同步服务端账号和工作区列表，直接进入已有任务的目标看板。监听主页面导航，全程未回到 `/onboarding`，也没有手工刷新；之后主动刷新，看板仍可访问。
2. **同步失败恢复**：第二位同事加入成功后，拦截随后首次 `GET /api/me`，返回模拟 503。页面留在加入结果，说明成员关系已保存，提供 Retry sync；此时数据库已有且仅有一条成员关系。点击重试后直接进入同一目标任务页。整个加入和恢复期间只有 **1 次** join POST；没有把同步失败当成邀请失效。
3. **已有成员**：两位同事重新打开同一有效分享链接、点击加入，均回到邀请指向的工作区。页面单元测试另覆盖账号首个工作区是 `other`、邀请目标为 `acme` 的情况，包括同步失败后的重试，保证不跳到首个工作区。

两条路径各自在看板刷新后都核对了持久化结果：`role=member`、`is_instance_admin=false`、`onboarded_at` 非空、成员关系数 1。

全部浏览器步骤结束、再次打开分享链接后，独立查询最终数据库：
