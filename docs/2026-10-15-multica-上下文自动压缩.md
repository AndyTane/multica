# Multica 上下文自动压缩（G）

2026-10-15 · Codex · 本地分支 `tane/main`

用户决定跳过 C，优先实现 G。此功能适用于 Multica 调用的 Claude Code 和 Codex；DSH 的网页会话不在本次范围内。

## 使用

打开智能体详情 → 设置 → 上下文压缩。默认开启，阈值为 **80,000 tokens**，每个智能体可以分别关闭或调整为 1,000～2,000,000。

- 成功运行结束后，达到阈值就趁原进程和连接仍在时压缩，然后才结束这次运行。
- 恢复一个已经超过阈值的会话时，先压缩，再提交新任务。
- 压缩使用原会话。历史会整理为摘要，会调用模型并产生用量；摘要不会替换本次任务的最终回复。

阈值按最近一次模型请求的上下文计算，包含缓存输入和输出，不使用累计计费 tokens。它是触发检查的阈值，不是上下文大小的硬上限：单次长任务中间仍由原工具的压缩机制负责。

前端负责人原有 `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000`，后端架构师原有 `-c model_auto_compact_token_limit=200000`，继续保留为单次长任务的原生兜底。G 在任务边界另做 8 万阈值检查。

## 失败与续接

Claude 每次压缩最多等待十分钟，Codex 保持两分钟，都支持取消并遵守调用方的整体时限。Claude 的计时从 SDK 初始化结束、开始提交 `/compact` 时启动。准备和压缩期间暂停接收补充输入，待这次运行收尾后再处理后续任务。

- 任务结束后的压缩失败、超时或进程退出：保留已完成任务及原回复，在运行日志提示压缩未完成。
- 新任务开始前的压缩失败：不提交新任务、不自动改用新会话；保留会话编号，修复原因后重试，或在智能体设置中关闭自动压缩。
- Claude 压缩超时会明确报告等待时限、任务未提交及会话保留，分类为超时；不再只给出“压缩未完成”的通用错误。
- 上下文计数缺失时不猜测。恢复前从原工具的会话记录末尾最多读取 8 MiB；损坏、尚未写完或只有压缩文件的记录可能无法提供计数，这时仍依赖原工具的原生压缩。

Claude 在同一个 stream-json 输入流发送 `/compact`，等待压缩边界和完成结果；Codex 使用 `thread/compact/start`，等待对应会话、轮次的 `contextCompaction` 与结束事件。接口返回“已接受”不算完成。

## 配置与维护

配置保存在现有 `agent.runtime_config.context_compaction` 中，不需要数据库迁移：

```json
{
  "context_compaction": {
    "enabled": true,
    "threshold_tokens": 80000
  }
}
```

缺少该项时采用默认值；API 拒绝写入无效的开关或阈值。设置页保存时保留其他运行配置。已有损坏配置会在守护进程日志告警并停用该项维护，修正并保存后生效。

SDK 的 `ExecOptions.ContextCompaction` 未设置时不主动压缩，守护进程负责给 Claude/Codex 传入智能体策略。压缩完成前不会释放运行，也不会让收尾超时覆盖已确认的任务结果。
