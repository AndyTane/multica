# Multica 会话恢复（F3 · B）

2026-10-14 · Codex · 分支：`tane/main`

恢复入口已构建并部署到本机网页、后端及 Windows 守护进程。运行详情现在支持复制 Claude/Codex 会话编号和恢复命令。DSH 沿用已有网页链接。

## 使用

1. 打开智能体某次运行的记录，点击右上角的 ⓘ。
2. 等待这个会话在 Multica 中的运行结束，点击「复制恢复命令」。
3. 在执行该任务的电脑上打开普通终端并粘贴。Windows 使用 PowerShell；Linux/macOS 使用兼容 POSIX 的 shell。
4. 命令检查运行和本机会话目录后，打开原来的 Claude 或 Codex 会话，继续输入即可。

恢复后是在原工具里手动续聊，后续回复不会自动同步到 Multica 任务。原会话可能仍包含 Multica 的提示词，手动续聊不会再注入该次运行的 Multica 凭据。

复制的命令使用本机 Multica 可执行文件的完整路径，包含工作区、守护进程配置档和任务目录根路径；不要求将 `multica` 加入 PATH。命令只在复制时包含本机路径，详情界面不展示这些绝对路径。

若按钮不可用，仍可复制会话编号。正在执行的运行需先结束；旧守护进程需更新并重新注册恢复信息。若在守护进程任务目录内运行，已有 CLI 保护会拒绝使用人类账户，改在普通终端的用户目录粘贴。

## 命令如何恢复

新增命令：

```text
multica agent resume <agent-id> <task-id> [--workspaces-root <root>] [--print]
```

它通过现有授权 API 读取运行历史、活动运行及运行时信息，拒绝仍在执行的同一会话。目录、会话编号或原运行时缺失时给出错误，不创建替代会话。

- Claude：切换到该次运行的目录，再执行 `claude --resume <session-id>`。若原工作树已清理，则使用运行响应提供的持久项目目录；会话记录是否仍可恢复由 Claude 自身判断。
- Codex：从已有任务目录索引、归属标记及会话记录确定对应的 `CODEX_HOME`，再执行 `codex resume <session-id> --cd <directory>`。原工作目录存在时优先使用它；已清理的工作树使用持久项目目录。独立会话目录仍保留，不改成默认 `.codex/sessions`。
- 缺少 CLI、目录或 Codex 会话记录：停止并显示原因。路径解析不会创建或迁移任务目录。

`--print` 只输出将使用的工具、目录、会话编号及参数，不启动智能体、不发送消息，可用于本机排查。手动恢复期间，请不要同时在 Multica 启动同一会话的新运行；检查只保证启动恢复时会话空闲。
