# Multica 改版计划（tane 自用版）

写于 2026-10-11 · Claude · 依据：Multica 源码 `a820c9a`（2026-10-10）
用户已选定「拉源码改版」。相关文档：[改造路线](2026-10-11-multica-改造路线.md)（各功能现状）、[DSH 桥设计](2026-10-11-multica-dsh-bridge-design.md)（改版里的功能 A）。

## 1. 先说清楚的几条

- **规模**：Multica 约 120 万行代码（Go 后端 + Next.js 网页 + Electron 桌面端 + 手机端），Postgres 数据库。
- **许可证**：只能自己用、跑在自己电脑上，不能开放给别人用；**界面上的 Multica 名称、Logo、版权信息必须保留**（Multica License 第 1(a)(b) 条）。
- **「删」的做法：摘掉入口，不删目录。** 把不要的功能从路由注册、菜单、设置页、构建清单里摘掉，代码目录原样留着。界面上看不到、后台也不加载，效果和删掉一样；但以后合并 Multica 官方更新时冲突少得多。直接删目录，每次官方改到那些文件都会冲突。
- **跑起来的方式**：数据库、后端、网页用 Docker Desktop 跑（从改版源码构建镜像）；干活的守护进程用改版源码编译的 `multica.exe`。桌面端先不改、不编译，用浏览器打开网页版就够了，以后需要再说。

## 2. 仓库

- 位置：`D:\01_Projects\multica-fork`（本地 git 仓库，不需要你在 GitHub 上操作）。
- 远端 `upstream` 指向官方仓库，只拉不推。改版的提交都在 `tane/main` 分支。
- 每个改动一个小提交，提交信息以区域开头（`strip:`、`feat:`、`ops:`），合并官方更新时一眼能看出哪些是我们的。

## 3. 删哪些（F0 之后按源码核实，大部分不用改代码）

读代码后发现，自托管版本里多数「不需要的功能」本来就不会运行，删它们反而徒增合并冲突：

| 功能 | 自托管下的实际情况 | 处理 |
|---|---|---|
| 飞书 / Slack / 钉钉 / 企业微信 / Telegram | 后端只有配置了各自的密钥（`MULTICA_LARK_SECRET_KEY` 等）才会启用，`server/cmd/server/router.go` 第 572、786、874、931、1186 行 | 不配密钥 = 已关闭，不改代码。设置里的「渠道」页还在，但只是空页 |
| 计费、席位 | 网页的计费页受功能开关控制，默认关（`settings-page.tsx` 第 113 行） | 不改 |
| 匿名部署遥测、产品分析 | 默认开 | `.env` 里设 `DO_NOT_TRACK=1`、`ANALYTICS_DISABLED=true`，不改代码 |
| 用不到的 AI 编程工具 | 守护进程只注册本机装了的命令行工具 | 不改，你机器上没装的不会出现 |
| 手机端、文档站、UI 实验室 | 自托管构建本来就不构建它们 | 不改 |
| 界面语言 | 设置 → 偏好里可以选简体中文，也会跟随浏览器语言 | 不改，原来第 4 节的 D 取消 |

## 4. 加哪些

| | 功能 | 做法 |
|---|---|---|
| A | **DSH 的活在 DSH 网页里看得到、能插话** | DSH 桥（见桥设计文档），改版里把它设为 DSH 运行时的默认命令；任务的执行记录里加「在 DSH 网页打开」链接 |
| B | **在原工具里接着聊** | 每次运行的详情里显示会话 id，并给出「复制恢复命令」：Claude 是 `claude --resume <id>`（在对应目录下），Codex 是 `codex resume <id>`，DSH 是网页链接 |
| C | **Codex 会话在 Codex 桌面端看得到** | 加一个开关，打开后 Multica 跑的 Codex 会话写进你平时的 `~/.codex/sessions`，而不是它单独的 `multica-sessions` 目录。官方单独存放是因为历史太多会拖慢 Codex，所以默认关，打开前先在你机器上量一下影响 |
| E | 合并官方更新的固定流程 | 一个脚本：拉官方更新 → 合并 → 跑测试 → 构建 → 报告冲突，不自动解决冲突 |
| G | **任务拖得再久，上下文也不涨**（2026-10-13 加） | 每次运行结束、进程退出前，守护进程看这个会话的上下文大小，超过阈值（默认 8 万）就趁缓存还热立刻压缩一次：Claude 在同一个输入流里发 `/compact`，Codex 走 app-server 的 `thread/compact/start`。下次叫醒续接的是压缩后的会话，隔几个小时也不用整段重写缓存。另加一条兜底：会话已经冷了又很大，先压缩再干活。阈值放进智能体设置，默认开 |

G 之前的临时措施（2026-10-13 已配，G 做完可以去掉）：前端负责人的 custom_env 加了 `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000`，后端架构师的 custom_args 加了 `-c model_auto_compact_token_limit=200000`，两边的会话到 20 万左右会自动压缩。起因是 CLAWSTA-2 前端负责人的会话 8 次运行后涨到 48 万，每次运行都要带着整段上下文。

## 6. 风险

- **F0 可能卡在环境上**：需要 Docker Desktop、Go 1.26.9、Node 22 以上、pnpm 10.28.2。缺哪个由你装（安装软件属于你的电脑配置，DSH 只检查、不安装）。
- **合并官方更新会持续有成本**：Multica 几乎每天都有提交。建议每两到四周合并一次，不追每一个版本。
- **登录**：自托管默认要邮箱验证码。只在本机用时，可以设成固定验证码（官方支持的本地开发设置），绝不能在对外可访问的机器上这么设。
