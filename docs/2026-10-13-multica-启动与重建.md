# Multica 自用版：启动与重建

适用于 `D:\01_Projects\multica-fork` 的 Windows 本机部署。PostgreSQL、后端和网页在 Docker Desktop 中运行；守护进程在 Windows 上运行。改版提交保存在 `tane/main`，不向官方仓库推送。

## 本机配置

先启动 Docker Desktop，在 PowerShell 中进入仓库：

```powershell
Set-Location -LiteralPath 'D:\01_Projects\multica-fork'
```

现有 `.env` 包含本机数据库、登录和签名配置，继续使用它，不要用模板覆盖，也不要提交到 Git。首次部署才复制 `.env.example` 并按 [自托管说明](../SELF_HOSTING.md) 配置。

本机 `.env` 已设置：

```dotenv
DO_NOT_TRACK=1
ANALYTICS_DISABLED=true
NPM_CONFIG_REGISTRY=https://registry.npmmirror.com
```

前两项关闭匿名部署快照和产品分析。修改后需要重新创建后端容器，单独 `restart` 不会载入新的环境变量。网页的分析配置由后端提供，不需要为此重建网页。Next.js 构建遥测也已在网页镜像中关闭。

`NPM_CONFIG_REGISTRY` 同时用于构建时下载 pnpm 和安装依赖；版本及完整性校验仍由根目录的 `package.json` 和 `pnpm-lock.yaml` 决定。模板和构建文件默认使用 npm 官方源，本机因为官方源连接失败而选择镜像。此设置只影响源码构建，不需要改系统的 npm 配置。Corepack 的设置见 [官方说明](https://github.com/nodejs/corepack#environment-variables)。

本机保留 F0 的 `APP_ENV=development` 和固定验证码 `888888`。网页、API 只绑定 `127.0.0.1`；固定验证码仅用于这个本机环境。

## 启动与检查

所有操作都带上源码构建配置，避免切回官方镜像：

```powershell
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml up -d --no-build --pull never
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml ps
Invoke-RestMethod -Uri 'http://localhost:8080/health'
Start-Process 'http://localhost:3000'
```

`--no-build --pull never` 使用本机已构建的镜像；首次部署应先执行下一节的构建。网页默认是 `http://localhost:3000`，后端默认是 `http://localhost:8080`。改过 `.env` 的端口时，用下面命令确认实际地址：

```powershell
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml port frontend 3000
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml port backend 8080
```

登录时先请求验证码，再输入本机固定验证码。已有账户、工作区和任务都保存在原来的数据库卷中。

## 修改后重建

先构建成功，再更新运行中的容器：

```powershell
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml build backend frontend
if ($LASTEXITCODE -ne 0) { throw '构建失败，现有服务仍可继续运行。' }
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml up -d --no-build --pull never
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml ps
Invoke-RestMethod -Uri 'http://localhost:8080/health'
```

只修改网页时，将构建命令最后的 `backend frontend` 改为 `frontend`；只修改 Go 后端时改为 `backend`。只修改 `.env` 的运行配置时，直接执行 `up -d --no-build --pull never` 即可。

网页构建现在会直接复制根目录声明的补丁文件。手机端的应用源码仍排除在 Docker 构建上下文之外；不需要 F0 临时 Dockerfile、额外的补丁目录或 `--build-context patchctx=...`。

查看日志：

```powershell
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml logs --tail 100 backend frontend
```

后端日志中应出现 `self-host telemetry disabled via DO_NOT_TRACK` 和 `analytics disabled via ANALYTICS_DISABLED`。若网页构建又出现 npm 下载失败，先核对 `.env` 的镜像地址以及 Docker Desktop 的网络；不要删除锁文件或关闭完整性校验。

## 停止，再启动

```powershell
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.build.yml stop
```

重新启动使用上面的启动命令。`stop` 保留容器和数据；`down` 也保留命名卷，但会移除容器和网络。不要使用 `down -v` 或 `make destroy`，它们会删除持久数据。

## 守护进程

网页镜像不会更新 Windows 上的守护进程。改动守护进程后，需要单独从此仓库构建。使用脚本写入 Git 源码版本，并先输出到另一个文件，避免覆盖运行中的程序：

```powershell
./scripts/build-local-cli.ps1 -GoExecutable 'D:/Tools/go/bin/go.exe'
if ($LASTEXITCODE -ne 0) { throw '守护进程构建失败。' }
```

输出为 `server/bin/multica-next.exe`，版本形如 `v0.6.1-43-ga331e19b9-dirty`。不要使用未写版本的构建，或自行写成 `dev` / `dev-g`；这些值无法通过“通过智能体创建”等功能的最低版本检查。

启动和登录沿用已有 CLI 配置；具体命令见 [CLI 与守护进程说明](../CLI_AND_DAEMON.md)。确认没有进行中的运行后，再停止旧守护进程、备份旧文件，将新文件复制为 `server/bin/multica.exe`，然后启动。保持 `--no-auto-update`，避免自用版被官方二进制替换。
