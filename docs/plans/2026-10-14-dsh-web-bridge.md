# F2：Multica 向 DSH 网页会话投递消息

用户已确认：在 Multica 里 @DSH，消息进入 DSH 网页会话，用户可以在网页查看和插话，结果回到 Multica。

## 实现边界

- 提供独立的 `multica-dsh-web` 桥命令，使用现有 DSH 协议，通过 Multica 已有的自定义运行时绑定 DSH 智能体。不启动另一套 DSH，也不改变网页进程的配置。
- 通过本机 DSH 网页 API 创建项目工作区和专用会话、投递消息及取消运行。新会话使用 `multica-web-` 前缀；后续运行使用 Multica 保存的会话编号。续接前核对项目路径和工作区归属，拒绝混用会话。
- 使用当前启动日志完成正常网页认证。认证信息只驻留内存，不写进提示词或结果。桥配置仅保存网页地址、启动日志路径和 DSH 数据目录。
- 读取网页进程产生的会话记录，转成 Multica 的文本、工具、用量和最终结果。以本次消息的 requestId 和 turn 编号定位结果，不把上次回复当作本次结果；投递状态不明时不自动重发。
- DSH 的模型、工具和 MCP 使用网页配置。桥的模型目录只提供“使用网页设置”，显式的其它模型或每次运行的 MCP 覆盖应报错。
- 网页进程不会继承守护进程的任务环境。生成任务专用 CLI 入口，保留已有任务凭据隔离；提示词只引用入口路径，凭据不进入会话记录。运行结束移除入口。
- 运行详情展示网页入口和会话编号。当前 DSH 未确认支持会话深链接，使用经过验证的网页首页，不编造 URL 参数。

## 开发与验证

1. 实现桥与假网页主机测试：首次消息、同会话续接、历史结果隔离、取消、投递不明、路径错误和配置错误。
2. 补全 DSH 后端的运行说明传递；增加 API 可选会话字段及畸形响应测试，接入共享运行详情。
3. 构建本机桥、守护进程、后端与网页；在现有运行环境绑定 DSH 智能体，保留原绑定便于回退。
4. 普通测试使用假主机和测试目录。真实模型验证遵守仓库的明确授权规则，单独记录结果。
