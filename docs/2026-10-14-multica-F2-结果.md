# Multica F2 开发结果

2026-10-14 · Codex · 分支：`tane/main`

DSH 网页桥和运行详情入口已开发、构建并部署到本机。用户授权后，两条真实模型消息的回复和同会话续接验证通过，F2 的桥接验收完成。

使用说明见 [DSH 网页接入](2026-10-14-multica-DSH-网页接入.md)，阶段定义见 [改版计划](2026-10-11-multica-改版计划.md)。

## 改动与行为

- 新增独立桥命令 `multica-dsh-web`，使用当前 DSH 网页主机的工作区、会话、提示词和取消接口。它不启动另一套 DSH；网页仍控制模型、工具和 MCP。
- 每个 Multica 会话保存 DSH 会话编号，后续消息续接原会话。读取会话记录时用本次消息编号和轮次筛选，拒绝项目路径不符和已有运行的会话。投递状态不明时提示去网页检查，不自动重发。
- 将任务说明传入网页会话。网页进程的环境独立，因此通过临时 CLI 入口传递任务凭据；凭据不写入提示词，运行结束清理临时入口。
- 运行详情增加“打开 DSH 网页”和复制会话编号。后端返回兼容旧客户端的可选字段，前端丢弃异常字段和含凭据的地址。
- 配置脚本复用或创建 DSH Web 运行时配置，并固定本机桥路径。不需要数据库迁移。

## 本机状态

- Multica 网页：`http://localhost:3000/`；后端：`http://localhost:8080/`。
- DSH 网页：`http://127.0.0.1:3080/`，继续使用原网页进程。
- “Agent观测站”已新增 DSH 智能体，绑定在线 DSH Web 运行时；模型 `web/default`，同时运行数为 1。
- 原有智能体保留。守护进程重启时发现桌面应用环境里的 Codex 路径已经失效，使用原来的 npm 命令路径启动后，原 Codex 运行时恢复在线；未修改系统环境变量。
- 桥配置位于用户的 `.multica/dsh-web.json`；后端 `.env` 已配置不含凭据的网页地址，两者均未提交到 Git。

目前网页入口打开 DSH 首页，需要在对应工作区找到 `Multica · ...` 会话；复制编号可用于核对。当前 DSH 版本未确认支持会话深链接，未编造链接参数。
